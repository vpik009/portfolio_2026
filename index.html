msc-thesis/orion.md

#ORION

Explainable AI for kidney transplant aftercare

type: M.Sc. thesislab: IESLab, University of Freiburgwhen: 2026 to 2027

A clinical decision-support system that predicts graft rejection, graft loss and mortality from irregular lab and vital time series, clinical notes and patient demographics. My part is to make the model explain itself, and to build an agent that checks its output against clinical guidelines.

  • Compared SHAP, Integrated Gradients and TIMING on 676 test patients, and measured how well each one matches what clinicians consider relevant.
  • Extended Concept Relevance Propagation to a time-aware LSTM. Wrote a custom relevance rule after finding that the default one silently passed relevance straight through multi-head attention.
  • Picked an LLM that runs on one 48 GB GPU inside the lab, because patient data can't leave it. Benchmarked gpt-oss-20b against Qwen3-32B-AWQ.
  • A custom Python agent (no framework) retrieves guideline passages and returns structured JSON with references, which feeds a Plotly Dash dashboard for clinicians.

projects/seer.py

#SEER

Offline reinforcement learning on cancer registry data

type: M.Sc. project, short paper for CIBB 2026when: 2025 to 2026

A dataset-agnostic Python framework that turns static tabular data into offline RL transitions, so any offline RL library can learn treatment policies from it without changes. I tested it on the US SEER cancer registry.

  • Processed 13.8 GB of raw data in chunks. Chose integer encoding over one-hot, which would have grown it past 120 GB.
  • Designed the reward: survival years, plus a bonus for being alive, minus a penalty for cancer death and for worse tumour grade. Domain experts can adjust the weights.
  • Folded 9 treatment dimensions into one discrete action space, so one model covers every treatment type.
  • Benchmarked four algorithms on 500k updates each. Found that synthetic augmentation hurt the best model, and that an apparent gain for BCQ was just training instability.
